# AMPS

**Мобільна соціальна мережа з пошуком аніме по картинці та музикою зі свободною ліцензією.**
Android-застосунок (Kotlin + Jetpack Compose) і власний Ktor-бекенд (Kotlin + PostgreSQL), розгорнутий на Railway.

Пакет `dev.amps.app` · актуальна версія — **1.6.5** · CHANGELOG — [CHANGELOG.md](CHANGELOG.md)

---

## Що це

AMPS — самодостатня соцмережа з сервером, яку можна тримати на власному backend:

- **Спільнота** — стрічка постів з фото/відео, лайки, репости, коментарі, опитування, хештеги;
- **Спільноти-групи як у ВКонтакте** — обкладинка, аватар, опис, ролі (власник 👑 / модератор 🛡 / учасник), запити на вступ, передача власництва, закріплені пости, посилання-запрошення;
- **Чати** — приватні діалоги і групові: реакції на повідомлення, видалення своїх, «друкує…», блокування користувачів;
- **Сторіс** — 24 години і зникають самі; **Рілси** — вертикальні відео 9:16;
- **Кружки** — круглі відео-повідомлення до 60 с у постах груп і чатах;
- **Профіль з XP і рівнями** — XP за пости, чати, групи, реакції; рівні, досягнення;
- **Пошук по картинці** — аніме-кадр → серія, персонаж, вики-сторінка (IQDB + AniList + trace.moe + офлайн-тегер);
- **Музика** — пошук метаданих і лише вільно-ліцензованих файлів (CC-ліцензії перевіряються в коді, не в інтерфейсі);
- **Оновлення по повітрю** — застосунок сам перевіряє релізи GitHub і ставить нові версії.

## Структура репозиторію

```
AMPS_MK/
├── app/                 Android-застосунок: Kotlin 2.0, Jetpack Compose, Material 3
│   └── src/main/java/dev/amps/app/
│       ├── core/        Локалізація (t()), компресія зображень, теми
│       ├── data/remote/ BackendApi (OkHttp), DTO, ImageLoader, Gemini/trace.moe клієнти
│       └── ui/screens/  community · groups · chats · reels · stories · music · wiki · profile
├── backend/             Ktor 3 + Exposed DAO + PostgreSQL (деплой на Railway)
│   └── src/main/kotlin/dev/amps/backend/
│           ├── model/       Tables + Entities + DTO (дзеркальний контракт із застосунком)
│           ├── service/     Feed, Chat, Group, Reel, Story, Profile, XP, MediaStorage…
│           └── routing/     socialRoutes (групи/чати/рілси), feedRoutes, authRoutes
├── demo/                Демо-прогон пошуку по картинці (живі відповіді сервісів)
├── docs/                Дослідження (музичні джерела)
└── keystore/            Релізний ключ (не комітиться)
```

Сервер і клієнт ділять один контракт — `ApiResponse<T>` конверт із
`data/error/errorCode`. DTO-класи продубльовані на обох сторонах навмисно:
збірки незалежні, а імена полів змінювати не можна.

## Можливості застосунку (1.6)

| Модуль | Що вміє |
|---|---|
| Спільнота | стрічка постів (фото, відео, кружки), сторіс 24 год, лайки, репости, коментарі, опитування, Instagram-формати фото |
| Групи | спільноти в стилі ВК: обкладинка, VK-шапка, ролі owner/mod/member, запити на вступ, закріплені пости, посилання-запрошення, передача власності |
| Чати | приватні і групові: фото (webp-компресія), реакції-перемикачі, видалення, «друкує…», блокування, непрочитані, миттєве надсилання (optimistic UI) |
| Рілси | вертикальні 9:16 відео, своя лента, лайки |
| Профіль | аватар, біо, XP/рівні, лідерборд, аніме-список, історія пошуку |
| Пошук аніме | кадр → IQDB + trace.moe + AniList + Wikidata + офлайн-тегер (ONNX, 166 МБ моделі вшито) |
| AI-аналіз фото | чат з Gemini про кадр; «Зберегти персонажа» → картка аніме в Колекціях, оновлення в реальному часі |
| Музика | пошук метаданих (iTunes/MusicBrainz) + завантаження тільки вільно-ліцензованих файлів (CC-фільтр у коді, не на кнопці) |

Серверна логіка: JWT-акаунти (+2FA TOTP, вхід через Google), XP-господарство,
RateLimiter антиспам, приватні вкладення чатів (роздача лише учасникам листування),
сховище медіа на Railway volume.

## Архітектура

```
Телефон (Compose)                       Railway (Ktor)
┌────────────────────┐                 ┌─────────────────────────┐
│ app: dev.amps.app  │ ── HTTPS/JWT ─▶ │ backend (Ktor 3)        │
│ OkHttp + kotlinx   │                 │ Exposed DAO 0.55        │
│ Coil, MediaPlayer  │                 │ PostgreSQL               │
│ ONNX-тегер (офлайн)│                 │ JWT access+refresh      │
└────────────────────┘                 │ /media роздача + volume │
                                       └─────────────────────────┘
```

- **Конверт відповіді:** `{"success": true, "data": …}` / `{"success": false, "error": …, "errorCode": …}` — єдиний для всіх ендпоінтів.
- **Авторизація:** JWT access + refresh, `Authorization: Bearer`.
- **Антиспам:** `RateLimiter` — 20 повідомлень/хв на чат, ліміти XP на добу.
- **Медіа:** `photo/`, `avatar/`, `private/`, `video/` каталоги; аватарки й обкладинки груп — публічні, вкладення чатів — тільки за участю в листуванні.
- **Схема БД:** `SchemaUtils.createMissingTablesAndColumns` на старті — нові колонки додаються автоматично, міграційний фреймворк для цього масштабу зайвий.

### Основні ендпоінти

```
POST /auth/*            реєстрація, вхід, 2FA, refresh, Google ID-token
GET  /feed              стрічка спільноти        POST /posts (multipart)
GET  /stories           сторіс (24 год)         POST /stories
GET  /groups            каталог груп             POST /groups/{id}/join
PUT  /groups/{id}       редагування (admin)      POST /groups/{id}/cover
POST /groups/{id}/transfer   передача власності   POST /groups/{id}/posts/{pid}/pin
POST /groups/{id}/invite     код-запрошення       POST /groups/{id}/invite/{code}/join
GET  /chats             діалоги                 POST /chats/{userId} — повідомлення
POST /chats/typing      «друкує…»               POST /chats/message/{id}/react
GET  /health            статус + версія (моніторинг Railway)
```

## Сборка

### Застосунок

Потрібні JDK 17, Android SDK (platform 35), Gradle 8.11+.

```bash
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Реліз (R8 + shrinkResources, підпис з `keystore/`):

```bash
./gradlew assembleRelease
```

Модель аніме-тегера (166,8 МБ) не в git — задача `:app:fetchAnimeTagger`
скачує її при збірці і **обов'язково звіряє SHA256**:

```bash
./gradlew :app:fetchAnimeTagger
```

### Backend

Kotlin + Ktor 3 + Exposed + PostgreSQL. Локально:

```bash
cd backend
./gradlew run          # підніме сервер на :8080
```

Деплой — Railway (`railway.toml`, Dockerfile). `/health` віддає
`{"status":"ok","version":"1.6.5","storage":"volume"}` — версія оновлюється
разом з релізом і слугує індикатором деплоя.

## Оновлення по повітрю

Застосунок сам перевіряє `GET /api/repos/Mugen00/AMPS_MK/releases/latest`
(без токена), порівнює тег `vX.Y.Z` з встановленою версією, качає APK
з прогресом і ставить через системний інсталятор. Перед установкою
перевіряється, що пакет — `dev.amps.app`. Деталі — у CHANGELOG.

## Приватність

- Дозволи: `INTERNET`, `ACCESS_NETWORK_STATE`, `CAMERA` (сторіс і кружки),
  `REQUEST_INSTALL_PACKAGES` (оновлення). Ніякого доступу до контактів.
- Ключів у APK немає: IQDB/AniList без реєстрації, Jamendo — відкритий
  client id. Немає чого витікати.
- Приватні вкладення чатів роздаються лише учасникам листування
  (Authorization-заголовок у Coil).
- Модель тегера працює офлайн; картинка пошуку йде лише на iqdb.org.

## Історія

AMPS починався як пошуковик по аніме-кадру (IQDB, trace.moe, AniList,
офлайн-тегер wd-swinv2-tagger) і пошук CC-музики — обидва модулі живі й зараз.
З 1.2.0 ядром застосунку стала **Спільнота**: акаунти, стрічка, сторіс, чати,
а з 1.6.0 — групи, XP-система, рілси. Детальні заміри точності пошуку,
таблиці сигналів RankingEngine і ліцензійна логіка — в
[docs/music-sources.md](docs/music-sources.md) та історії релізів.
