# AMPS

**Поиск по кадру аниме и по музыке.** Android-приложение, которое по скриншоту
находит серию и сцену, собирает вики-страницу с персонажами и источниками,
а по названию трека — метаданные и свободно лицензированный файл.

Рабочее название — **AMPS**. Пакет `dev.amps.app`, версия 1.0.0.

---

## Зачем это

Обычный поиск по картинке аниме отвечает на вопрос «что это за картинка».
AMPS отвечает на два вопроса сразу: **откуда кадр** (серия, эпизод, таймкод,
сцена) и **что за произведение** (описание, студия, персонажи, связи,
рекомендации, лицензия на изображение). По названию песни приложение находит
исполнителя, альбом, обложку и — если у источника есть свободная лицензия —
сам файл с указанием авторства.

Ключевая деталь: **телефон не ходит в интернет за аниме-поиском напрямую.**
Он обращается к вашему компьютеру по Wi-Fi, а тот вызывает MCP-серверы,
установленные в DeepSeek Harness. Поэтому trace.moe и imgfind работают с теми
же квотами и ключами, что и в вашем агенте, а не с телефона.

С версии 1.0.1 **ничего вводить не нужно**. Мост отвечает на UDP-широковещание
и сообщает свой адрес сам; если моста в сети нет, приложение обращается к
публичному HTTPS-API trace.moe напрямую — серия, эпизод и таймкод
определяются в обоих случаях.

## Как это работает

```
┌──────────────┐   Wi-Fi / HTTP    ┌──────────────────┐   JSON-RPC 2.0   ┌────────────────┐
│    Телефон   │ ────────────────▶ │  bridge (:8787)  │ ──── stdio ────▶ │ trace-moe-mcp  │
│  dev.amps.app│   POST кадра      │  Node, 0 зависим.│                  │ imgfind-mcp    │
└──────┬───────┘                   └──────────────────┘                  └───────┬────────┘
       │                                                                   │
       │  HTTPS                                                           │ MCP-ответ
       ├──────────────▶ AniList GraphQL   описание, персонажи, связи        │
       ├──────────────▶ iTunes             метаданные трека                 │
       ├──────────────▶ MusicBrainz        метаданные + MBID                │
       ├──────────────▶ Cover Art Archive  обложки                          │
       ├──────────────▶ Internet Archive   свободные файлы + лицензия        │
       └──────────────▶ ccMixter           свободные файлы + лицензия        │
```

### Мост

`bridge/` — 5 файлов на стандартной библиотеке Node, без `npm install`.
Он поднимает MCP-серверы как дочерние процессы, говорит с ними по
newline-delimited JSON-RPC 2.0 и отдаёт результат телефону по HTTP.

| Эндпоинт | Что делает |
|---|---|
| `GET /api/health` | готовность обоих MCP-узлов, список инструментов, ключи, блок `discovery` |
| `POST /api/frame/identify` | кадр → trace.moe + SauceNAO + AniList |
| `GET /api/frame/lookup` | поиск серии по `anilistId` без картинки |
| `GET /api/anime/search` | поиск серии по названию |

### Как телефон находит мост

Мост слушает **UDP 8788** и отвечает на пакет `AMPS_DISCOVER_V1`:

```json
{"service":"amps-bridge","protocol":1,"version":"1.1.0",
 "http":"http://192.168.1.5:8787","port":8787,"host":"PC",
 "keys":{"traceMoe":false,"sauceNao":false},
 "mcp":{"tracemoe":true,"imgfind":true}}
```

Адрес в ответе собирается из того IP, с которого пришёл пакет, — ровно тот,
по которому телефон уже достучался до компьютера. Приложение рассылает запрос
в подсеть, проверяет найденный адрес через `/api/health` и кэширует его на
10 минут.

Ключи запуска: `--port` (HTTP, по умолчанию 8787) и `--discovery-port`
(UDP, по умолчанию 8788; значение `0` выключает автопоиск). Занятый UDP-порт
не роняет HTTP — мост продолжает работать.

Если моста в сети нет вообще, приложение отправляет кадр напрямую в
`https://api.trace.moe/search` — публичный ключ не нужен. Теряются только
теги SauceNAO, то есть автоматическое определение персонажа.

**Ключи (необязательны), `bridge/.env`:**

```
TRACE_MOE_API_KEY=...     # trace.moe работает и без ключа — квота по IP
SAUCENAO_API_KEY=...      # нужен, чтобы определять персонажа автоматически
```

### Определение персонажа

С этим пунктом важно быть честным, потому что обман здесь лёгкий.

- **trace.moe** определяет только произведение, эпизод и таймкод. Персонажа
  он не определяет вообще.
- **imgfind** возвращает SauceNAO одной строкой текста, в которой массивы
  `characters` и `tags` всегда пустые. Мост их выбрасывает.
- Поэтому мост делает **второй запрос напрямую в SauceNAO API**
  (`output_type=2`), где структура сохранена, и возвращает телефону
  `characters`, `tags`, `series` и `copyright` по каждому совпадению.
  Это работает, только если задан `SAUCENAO_API_KEY`.
- **Без ключа** приложение не выдумывает персонажа: оно показывает список
  кандидатов из AniList (роль, описание, появления) и даёт выбрать вручную.
  Это осознанное поведение, а не заглушка.

## Экраны

**Кадр.** Выбор изображения (системный выбор файла) или «поделиться» из
галереи. Кадр уменьшается до 1280 px и уходит на мост. Пока идёт поиск —
стадия прогресса; потом результат с круговым индикатором сходства.

**Вики.** Страница произведения:

- баннер, название, японское название, синонимы, чипы (год, формат, серии, статус);
- блок «Кадр найден» — серия, таймкод, движок, ссылка на сцену trace.moe, совпадение SauceNAO;
- сам найденный кадр из серии;
- описание, жанры, студия, оценка, популярность;
- персонаж с портретом, описанием, возрастом, кровью и списком появлений;
- похожие изображения (все совпадения SauceNAO) и рекомендации AniList;
- список источников со ссылками — что откуда взято.

**Музыка.** Три вкладки: поиск, свободные треки, мои файлы. Поиск с debounce
420 мс. Метаданные сливаются по нормализованному ключу `исполнитель + название`:
при коллизии побеждает iTunes, строка MusicBrainz используется, только если
добавляет MBID. Вики-страница трека — обложка, лицензия, спецификация
(формат, битрейт, частота, длительность), источники, похожие треки и
настоящее воспроизведение через `MediaPlayer`.

**Настройки.** Адрес моста, автопроверка связи, история, тема, сведения о
приложении и честный список источников музыки.

**История.** Последние 60 находок — и кадры, и треки. Нажатие открывает
соответствующую вики-страницу.

## Лицензии: как это решается в коде

Правило простое: приложение не отдаёт файл, у которого нет читаемой свободной
лицензии. Это не надпись в интерфейсе, а структура типов.

- У `MusicSearchResult` **вообще нет аудиополя**. К строке из iTunes или
  MusicBrainz физически нельзя прикрепить кнопку скачивания. `previewUrl`
  из iTunes намеренно не разбирается.
- У `FreeTrack` есть `downloadable = license.isKnown && !audioUrl.isNullOrBlank()`.
  `isKnown` требует **и** название лицензии, **и** её URL. `fromUrl()` никогда
  не превращает неизвестную лицензию в известную.
- `MusicRepository.download()` перепроверяет лицензию **до открытия сокета**
  и бросает `IOException`, если она нечитаема.
- Флаги CC разбираются из пути URL (`/licenses/by-nc-sa/4.0` → by + nc + sa,
  версия 4.0), а не угадываются по подписи. Из них формируются обязанности:
  «требует указания автора», «только некоммерческое», «те же условия».
- `FreeTrackFilter.OPEN` перепроверяет лицензию на клиенте, потому что
  archive.org не умеет выразить «CC, но не NC» в своём языке запросов.
- Каждый скачанный или импортированный файл получает рядом
  `<файл>.kagami.json` с источником, идентификатором, автором, ссылкой,
  лицензией, атрибуцией и sha256 — обязанность CC-BY переживает переустановку.

Чего приложение **не** делает: не вытаскивает аудио из YouTube, Spotify,
Яндекс.Музыки и Deezer, не обходит DRM, не трогает закрытые по лицензии
записи. Свой файл импортируется системным выбором — это легально по
определению, и лицензия для него помечается «не указана (свой файл)» с
возможностью дописать её вручную.

## Обновления по воздуху

С 1.0.1 приложение само следит за релизами в этом репозитории — так же,
как это делает F-Droid.

1. При запуске спрашивает `GET /api/repos/Mugen00/ASMP/releases/latest`.
   Репозиторий публичный, токен и никакие права не нужны.
2. Тег вроде `v1.0.1` разбирается в тройку (1, 0, 1) и сравнивается с
   установленной версией. Если новая больше — появляется сообщение
   «Доступно обновление».
3. APK скачивается с прогрессом, во временный файл, затем переименовывается.
4. Перед установкой проверяется, что в файле пакет `dev.amps.app`: чужой APK
   из релизов не поставится.
5. Установка идёт через системный установщик (`ACTION_INSTALL_PACKAGE`).
   Если система ещё не разрешила ставить из неизвестных источников,
   приложение объясняет это и открывает нужный экран настроек, а установка
   продолжается после возврата.

Все изменения каждой версии — в [CHANGELOG.md](CHANGELOG.md) и в примечаниях
к релизу.

## Сборка

Нужны JDK 17, Android SDK (platform 35, build-tools 35.0.0), Gradle 8.11+.

```bash
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Релиз с минификацией R8 и сжатием ресурсов:

```bash
./gradlew assembleRelease
```

**Подпись.** Положите `keystore/amps.jks` и `keystore/keystore.properties`
со строкой `storePassword=…` — сборка подпишется релизным ключом.
Если файлов нет, используется отладочная подпись, и сборка всё равно
проходит. Сам ключ и его пароль в git не попадают (проверено `.gitignore`).

| | debug | release |
|---|---|---|
| размер | 18,4 МБ | **1,77 МБ** |
| applicationId | `dev.amps.app.debug` | `dev.amps.app` |
| минификация | нет | R8 + shrinkResources |

## Демо-прогон

`demo/` — не выдумка, а запись реального запроса.

Кадр взят из Wikimedia Commons (CC BY 3.0, HoneyWorks OFFICIAL), отправлен в
живой мост, ответ разобран тем же кодом, что и в приложении:

| | |
|---|---|
| Серия | Heroines Run the Show / ヒロインたるもの！ |
| AniList / MAL | 138459 / 49692 |
| Эпизод, таймкод | 8 / 12, 11:36 (696,78 с) |
| Сходство trace.moe | **99,6 %** |
| SauceNAO | 92,35 %, индекс AniDB |

Внутри: `anilist-138459.json` — сырой ответ AniList, `wiki.html` — страница
для браузера, `kagami-wiki-demo.png` — отрисованная вики, `render_wiki.py` —
её генератор, `bridge-identify.json` — ответ моста.

Ограничение этого кейса честно зафиксировано: у видеокадра нет тегов
персонажа, поэтому в демо показан список кандидатов, а не уверенное
определение. На арте персонаж определяется автоматически, когда задан
`SAUCENAO_API_KEY`.

## Что ещё стоит знать

- Приложение просит ровно два разрешения: `INTERNET` и `ACCESS_NETWORK_STATE`.
  Никакого доступа к галерее или хранилищу — файл выбирается через
  Storage Access Framework, доступ к нему выдаётся на одну операцию.
- Один жест «поделиться» из галереи: intent-фильтр принимает только
  изображения, и кадр сразу уходит в поиск.
- Ключ trace.moe не обязателен: без него работает анонимная квота по IP
  (100 запросов в сутки).
- Мост не хранит изображение дольше, чем на один вызов: файл пишется во
  временный каталог и удаляется в `finally`.
- История лежит в JSON-файле приложения (60 записей), библиотека музыки —
  в `filesDir/audio/library.json`.
- Поиск обновлений ходит на `api.github.com` без токена: публичный
  репозиторий, сколько угодно запросов не потратит ваши права.
- `REQUEST_INSTALL_PACKAGES` — «особое» разрешение, его нельзя выдать молча.
  Android спросит один раз, когда вы впервые нажмёте «Установить».
